# Property contact privacy and support-to-dispute handover

Migration: 2043_support_dispute_handovers.sql. Existing support and dispute records remain intact. No new provider, subscription, payment amount or environment variable is added.

Customer property routes now remove phone/email/contact fields recursively, including unlocked details and property participants. Public location and published damage-report queries no longer select landlord emails or phone numbers. Non-admin agent profile assignments omit landlord contacts. Separate authorised admin property/assignment endpoints retain contact fields behind their existing permissions. Free-form legacy property descriptions containing detected contact information are hidden in customer responses without editing stored records. Phone, email and WhatsApp shortcuts were removed from web and shared Android/iOS property screens. In-platform calls, tours, applications, property address/media unlock and payment security remain intact. Unlock wording no longer promises landlord contact details.

A scoped support officer prepares a title, shared summary, property and other party, and may choose a matching existing open dispute. The named case officer is retained where an existing case already has one. Only the customer owning the ticket may accept, with explicit consent, or decline. New disputes and links are created only after acceptance. The other party receives no notification before acceptance. Private support replies, internal staff notes, private contact forms and attachments are not copied. Existing-case links publish only the approved summary as a dispute message. The request and its audit record are atomic; acceptance uses a database transaction, row locks and unique pending/accepted ticket indexes to prevent duplicate cases. Permissions, territory and current participants are checked again before acceptance.

The support officer responsible for the case can follow its formal record. This is a case-follow-up role, not automatic appointment as a neutral mediator or legal representative. Existing lawyer authorisation, conflict checks, assistance coverage and formal resolution permissions remain authoritative. This change does not introduce a new settlement-acceptance stage or automatically file an external case.

Formal case opening, new/edited messages, evidence upload/review, shared summary changes, recorded resolution, sealing and accepted handovers use the existing notification storage and push provider. Alerts go to the parties, named case officer and actively authorised lawyers within their territory; the actor is excluded from ordinary updates and included in case-opening confirmation. Alert text is generic and excludes private case text. A stored notification feeds the existing unread count and push badge. Notification permission, registered device tokens and launcher support still determine what the phone can display. Some Android launchers show a dot rather than a number. No real customer messages or push alerts are sent by tests.

The handover and private contact panels are available in Messages, support pages, staff ticket conversations, both website widgets and their shared Android/iOS screens. Guests never fetch private form records. Customer handover copy supports English, Hausa, Yoruba, Igbo, Arabic, French, Russian and Chinese; staff controls remain English. Website ticket deep links reuse the existing scoped conversation screens. Native dispute/ticket deep links open the right screen; reading a pushed notification refreshes the real unread count. The Super Admin Explore screen registration fix is included in mobile source.

Text contact protection is also enforced for formal dispute messages/edits and shared outcomes. Detection remains heuristic: it does not OCR property photos or scan audio/video for spoken or pictured contact details. Evidence itself is preserved. No automatic deletion of existing support/dispute records is introduced.

Validation: backend unit/regression suite; web component and regression suite; production React build; shared React Native/Babel checks; scripts/verify-super-admin-explore.cjs, scripts/verify-dispute-alerts.cjs, scripts/verify-notification-badges.cjs, scripts/verify-app-badge.cjs, and existing registration/embedded-payment checks. Final deployment logs record actual counts and results. Android release target: 1.0.60 build 71. iOS shared source: 1.0.60 build 65; an iOS binary requires a Mac build/signing environment.
